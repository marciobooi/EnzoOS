### A.2 Live regression re-check — the audio bridge (most important)

The 2026-07-02 playback outage fix **changed** §9.1's implementation after
TODO.md was closed out: `52-resonance-aloop-sink.conf` no longer opens raw
`hw:Loopback,0,0` (that raced MPD/librespot's `camilla_input` dmix for
exclusive device ownership — whoever opened it first won, the others got
"Device or resource busy") and now targets the `camilla_input` dmix PCM
itself. MPD and Spotify were user-confirmed working after that change, but
the **PipeWire-routed path** (AirPlay/Bluetooth/browser) had not been
re-verified through the new dmix target.

**Re-verified live 2026-07-03** on the VM: played audio through PipeWire's
`ResonanceInput` sink while sampling CamillaDSP's `GetCaptureSignalRms` —
signal measured at −18…−54 dB tracking the test audio's dynamics (−106 dB in
the silence between repeats, proving it wasn't a stuck reading), and
`pw-link -l` shows the intended topology: source → ResonanceInput →
loopback.capture/playback → resonance-aloop-sink → camilla_input (dmix) →
snd-aloop → dsnoop → CamillaDSP. **All three writer paths (MPD, librespot,
PipeWire) now coexist through dmix. No regression.**

TODO.md §9.1's text was corrected in this commit to describe the current
dmix-target design (its "static node for hw:Loopback,0,0" wording described
the superseded first version, which is exactly the config that caused the
playback outage).

## Part B — React frontend audit

Tooling: `npx eslint .` (eslint 10, `eslint-plugin-react-hooks` 7 with the
React-compiler-derived rules — much stricter than the classic plugin), plus
manual review of every error-severity hooks finding. Raw totals: **148
errors / 43 warnings**, dominated by `no-unused-vars` (62), `no-empty` (46
— all intentional `catch {}`), `react-hooks/exhaustive-deps` (40).

### B.1 Real findings

- **[MED] `Kiosk.jsx` — the `Kk` context `useMemo` never holds.** The
  `kioskCtx` memo (≈line 1281) lists ~20 handler functions
  (`handleToggleSource`, `handlePlayRadio`, `handleEqPresetChange`, …) as
  dependencies, but none are wrapped in `useCallback` — they're recreated
  every render, so the memo recomputes every render and **every `Kk`
  consumer re-renders on every Kiosk render** (which, with a 5 s status
  poll, 100 ms VU meter, and progress ticker, is constant). The memo
  currently adds cost without preventing anything. Fix is mechanical but
  wide: wrap the ~20 handlers in `useCallback`, or split `Kk` into a
  state-context + a stable actions-context. Same pattern exists in
  `RemoteControl.jsx`'s `ctxValue` to a lesser degree. Not fixed in this
  pass — flagged for a dedicated PR since it touches every handler
  signature and needs careful dependency lists.

- **[LOW] `react-hooks/set-state-in-effect` ×14** — classified individually:
  all are either the standard loading-flag pattern (`setLoading(true)`
  before an async fetch: QueuePanel, LibraryTab, LyricsSheet, RadioPanel,
  UniversalSearchOverlay, SystemAdminOverlay — the §3 fix that moved
  `loadStorage()` into an effect is itself one of these, correctly so) or
  small derived-state syncs (`if (!radioCountry) setStationsList([])` in
  Kiosk, `setStationsList(favoriteStations)` in RemoteControl). Each costs
  one extra synchronous re-render; none loop. Acceptable as-is; convert to
  derived values/`useMemo` opportunistically when touching those files.

- **[LOW] `exhaustive-deps` ×40** — most are deliberate mount-only fetches
  (`[]` with API calls) or the intentionally-narrowed sleep-timer deps from
  TODO §3 (documented there). Two worth an eventual look:
  `DefinitionsMenu.jsx:53` (`updateStatus` omitted — could show a stale
  update badge) and `LyricsSheet.jsx:48` (`album`/`duration` omitted —
  lyrics may not refetch when the same title switches album). Neither is
  user-visible enough to fix blind; verify behavior first.

- **[INFO] Dead code drift (`no-unused-vars` 62)** — notable clusters:
  `PlayerDisplay.jsx` `stepVolumeUp`/`stepVolumeDown` (feature built, never
  wired), `RadioPanel.jsx` `FrequencyBand`/`EmptyBand` components +
  several unused props, a dozen `import React` leftovers (unneeded since
  the JSX transform), unused icon imports. Safe bulk cleanup candidate —
  `npx eslint . --fix` handles none of these automatically (they need
  review since some may be intended features), so do it as a supervised
  pass.

- **[FP]** `WelcomeWizard.jsx:451 react-hooks/refs` — flagged "ref access

## Part C — Server audit

### C.1 Verified clean

- **Shell injection:** every exec that carries request-derived input uses
  `execFilePromise` with array args (`mpc add <path>`, `nmcli connect`,
  `timedatectl`, playlist names pre-sanitized with `[^\w\s\-_.]` strip).
  The remaining template-literal `execPromise` calls interpolate only
  server-side constants (hard-coded unit names, `MUSIC_DIR` env, module
  temp paths) — none reachable from request data.
- **Rate limiting:** `/api` 3000/15 min global; `/api/auth` 40/15 min. The
  new `POST /api/auth/pair-code` is covered by the auth limiter — 40
  attempts per 15 min against a 6-digit space (1M) with 10-min single-use
  TTL ≈ 27 guesses per code lifetime; brute force is not viable.
- **WS auth:** both upgrade handlers (HTTP 5000 + HTTPS 5001) enforce
  `isWsAuthorized` (loopback or signed token) before `handleUpgrade`.
  The three `no-useless-assignment` lint hits here (`let pathname = ''` /
  `let token = null` initializers before try/catch reassignment) are style
  noise, not logic bugs — verified the fallback branches are correct.
- **Error handling:** routes consistently use `sendError`/`AppError`; the
  46 `no-empty` lint errors are all deliberate `catch {}` on best-effort
  operations (matches house style, though `catch { /* why */ }` comments
  would silence the rule and document intent).
- **camilla-ws.js:** FIFO promise queue is timeout-guarded (1.5 s) so a
  dropped CamillaDSP reply can't leak pending promises; reconnect loop
  backs off at 2 s. OK.

### C.2 Findings

- **[LOW] `recently-added` smart playlist stats the whole library at once.**
  `getRecentlyAddedTracks()` fires `Promise.all(fs.stat…)` across every
  file `mpc listall` returns — unbounded concurrency. Fine at appliance
  scale (thousands of files → one brief FD spike, then 5-min cache), but a
  100k-file NAS-mounted library would open 100k stats simultaneously. Cap
  with a small concurrency pool (e.g. 64) if large libraries become a
  target.
- **[CLEANUP] Temporary iOS diagnostic still in the tree** —
  `POST /api/system/client-viewport-debug` (server/system.js) and the
  paired reporting effect in `RemoteControl.jsx`, both clearly marked
  `TEMP DIAGNOSTIC`. Deliberately left in while the iOS 26 standalone
  layout issue is still being tuned by hand; **remove both once the
  home-screen layout is confirmed done.**
- **[INFO] No automated test suite.** `npm run lint`, `node --check`
  (`check:server`) and `bash -n` (`check:scripts`) are the only gates —
  and lint currently fails with 148 errors, so it can't be enforced until
  Part B's cleanup lands. Suggested order: dead-code pass → fix/annotate
  the deliberate lint suppressions → then wire `npm run lint` into
  `scripts/update.sh`'s pre-restart checks.

## Verdict

Every TODO.md `[x]` claim checks out in code, and the one place where a
later fix rewrote an earlier fix's mechanism (the PipeWire bridge) was
re-verified live end-to-end with signal measurements. The React codebase's
one structural issue is the defeated context memoization in `Kiosk.jsx`
(worth a dedicated pass); everything else found is hygiene. The server
surface is in good shape: no injection paths, sane rate limits including
the new pairing-code endpoint, and consistent error handling. Open items:
Bluetooth WirePlumber rule needs a Lua rewrite + live pairing test, the
temp iOS diagnostic needs removal after the layout work settles, and the
44.1/48 kHz rate-switch test still wants real audio files.
